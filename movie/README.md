# 🎬 무비 박스 Movie Box

---

## 1. 프로젝트 소개
최신 박스오피스 순위와 개봉 예정작 정보를 한눈에 탐색하고 각 영화의 공식 예고편을 즉시 감상할 수 있는 반응형 웹 플랫폼입니다.

---

## 2. 프로젝트 개요
- **제작 배경**: 영화 정보 탐색과 예고편 감상을 별도 사이트 이동 없이 효율적으로 처리하고자 기획되었습니다.
- **기획 의도**: 사용자에게 직관적인 UI를 제공하고 다양한 디바이스 환경에서 일관된 영화 정보를 전달하는 것을 목표로 합니다.
- **프로젝트 목표**:
  - 사용자 친화적인 정보 구조(IA) 설계
  - 다양한 화면 크기에 대응하는 반응형 웹 구현
  - 동적 콘텐츠(예고편) 제어를 통한 사용자 경험 개선

---

## 3. 주요 기능
- **GNB & 드롭다운 네비게이션**: 마우스 호버 시 부드러운 슬라이드 인터랙션으로 메뉴 노출
- **카테고리 탭 스위칭**: '무비차트'와 '상영예정작' 데이터 즉각 전환
- **YouTube 트레일러 플레이어**: 포스터 클릭 시 공식 예고편 동적 로딩 및 재생
- **반응형 레이아웃**: PC 환경의 포스터 그리드와 모바일 환경의 순위 리스트 뷰 자동 전환

---

## 4. 기술 스택

| 분류 | 기술 |
| :--- | :--- |
| **Markup / Template** | `Pug` |
| **Styling** | `SCSS (Sass)`, `Google Fonts`, `Xeicon` |
| **Script / Library** | `JavaScript (ES6+)`, `jQuery 3.6.0` |

---

## 5. 기술 선택 이유
- **Pug**: 중첩된 HTML 구조를 간결하게 작성하여 유지보수성 향상
- **SCSS**: `@mixin`을 통한 레이아웃 모듈화 및 `@for` 반복문을 통한 에셋 자동 관리
- **jQuery**: 복잡한 DOM 조작 및 트레일러 제어 인터랙션을 빠르고 안정적으로 구현

---

## 6. 시스템 아키텍처
본 프로젝트는 데이터베이스나 별도의 백엔드 서버 없이 브라우저 단에서 동작하는 정적 웹 서비스입니다.

```text
[사용자 브라우저 (Client)]
       |
       +--- [정적 파일 로드 (HTML/CSS/JS/Images)]
       |
       +--- [외부 API: YouTube Iframe Player (트레일러 재생)]
```
*   **구조**: Pug(Template) -> HTML, SCSS(Style) -> CSS, JavaScript(Interaction)로 컴파일된 정적 자산을 브라우저가 렌더링.
*   **외부 API**: 유튜브 공식 API(Iframe)를 연동하여 트레일러 재생 기능 구현.
*   **데이터**: DB를 별도로 두지 않고 클라이언트 코드 내(스크립트)에서 영화 이미지 경로 및 예고편 데이터 관리.

## 8. 트러블 슈팅

### 1. 탭 전환 시 상호 배타적 컨테이너 제어
- **문제**: '무비차트'와 '상영예정작' 탭 전환 시 두 리스트가 겹치거나 이전 탭의 요소가 잔류하는 시각적 충돌 발생.
- **원인**: 탭 전환 로직에서 활성/비활성 컨테이너의 표시(`show`/`hide`) 처리가 명확히 분리되지 않음.
- **해결 과정 (Why/How)**: jQuery의 `toggle()` 함수에 탭 상태값(`isChart2`)을 인자로 전달하여 활성 상태에 따라 각 컨테이너(`.movie_img_box` / `.movie_img_box2`)를 상호 배타적으로 제어하도록 로직을 변경하였습니다. 결과적으로 리스트 간 간섭 없이 즉각적인 탭 전환이 가능해졌습니다.

### 2. 예고편 전환 시 오디오 잔류 방지
- **문제**: 트레일러 포스터를 클릭하여 영상 변경 시 기존에 재생 중이던 YouTube `<iframe>`의 오디오가 백그라운드에서 계속 출력되는 현상.
- **원인**: DOM 요소를 `hide()` 처리하더라도 브라우저 내 스트리밍 상태는 정지되지 않고 유지되기 때문.
- **해결 과정 (Why/How)**: 트레일러 전환 및 탭 전환 시 호출되는 `stopAllTrailers()` 함수를 정의하였습니다. 이 함수는 모든 트레일러 `<iframe>`의 `src` 속성을 강제로 재할당하여 기존 영상 재생을 확실하게 정지 및 초기화하도록 개선하였습니다.

### 3. SCSS 반복문을 통한 에셋 관리 자동화
- **문제**: 24개 이상의 영화 포스터 클래스를 개별적으로 선언하여 관리함에 따라 코드 중복이 심하고 유지보수가 어려움.
- **원인**: CSS 스타일의 반복적인 선언으로 인한 코드 파편화.
- **해결 과정 (Why/How)**: SCSS의 `@for` 제어문과 삼항 연산자를 활용하여 이미지 파일 번호와 클래스 선택자를 동적으로 매핑하였습니다. 단 몇 줄의 제어문으로 전체 에셋의 배경 경로를 자동 생성하여 코드 효율성을 극대화하였습니다.

## 9. 성능 개선

### 성능 개선 포인트
- **CSS 코드 모듈화 및 최적화**: SCSS 반복문(`@for`)을 활용한 스타일 선언 자동화
- **브라우저 리소스 효율화**: jQuery 기반 이벤트 핸들링을 통한 DOM 조작 및 외부 API(Iframe) 리소스 초기화 최적화

### 개선 전/후 수치 및 측정 방법
| 구분 | 개선 전 | 개선 후 | 측정 방법 |
| :--- | :--- | :--- | :--- |
| **CSS 코드 가독성/용량** | 24개 클래스 개별 선언 (약 150줄) | 제어문 활용 선언 (약 20줄) | 코드 라인 수 직접 비교 |
| **Iframe 리소스 제어** | 영상 전환 시 이전 영상 백그라운드 재생 잔류 | 전환 즉시 영상 스트리밍 정지/초기화 | 브라우저 개발자 도구(Network 탭) 확인 |
| **탭 전환 응답속도** | 로직 분리 미흡으로 인한 UI 버벅임 발생 | 즉각적인 컨테이너 toggle 전환 | 사용자 체감 속도 및 DOM 이벤트 렌더링 확인 |

## 10. 실행 및 테스트 방법

### 로컬 환경 요구사항
- **브라우저**: Chrome, Edge, Safari, Firefox 등 최신 웹 표준을 지원하는 브라우저
- **빌드 도구 (선택 사항)**: 소스 코드(Pug, SCSS) 수정 시 각각의 컴파일러(예: `pug-cli`, `sass`)가 설치된 Node.js 환경 필요

### 설치 및 실행 명령어
본 프로젝트는 별도의 서버 구축 없이 정적 파일로 동작하므로 `npm` 의존성 설치가 필요 없습니다.

1. **프로젝트 클론**:
   ```bash
   git clone [레포지토리-URL]
   ```
2. **웹 페이지 실행**:
   - `build/html/movie.html` 파일을 로컬 파일 시스템에서 직접 클릭하여 열거나 브라우저 주소창에 해당 경로를 입력합니다.
   - (권장) VS Code의 'Live Server' 확장 기능 등을 사용하여 로컬 서버 환경에서 구동하면 실시간 변경 확인이 가능합니다.

### 테스트 실행 방법
- **UI/UX 테스트**: 각 브라우저의 개발자 도구(F12)를 통해 반응형 모드(768px 이하/초과)를 전환하며 레이아웃 및 기능 정상 작동 확인
- **기능 테스트**:
  - 메뉴 마우스 호버(GNB 슬라이드) 확인
  - 탭 전환 시 상호 배타적 리스트 노출 확인
  - 포스터 클릭 시 YouTube 트레일러 영상 동적 전환 확인 (브라우저 콘솔 에러 확인)
