# [SECURITY] DevCodeHub - 보안 표준

실제 코드에 구현된 항목만 적습니다.

## 1. 인증·인가
- **JWT(stateless)**: 서버 세션을 두지 않습니다. 소셜 로그인 성공 후 토큰은 쿼리가 아닌 URL fragment(`#token=`)로 프론트에 전달해 서버 로그·Referer에 남기지 않습니다.
- **URL 규칙**: `/api/v1/admin/**`는 ADMIN 전용이며 규칙 순서상 가장 앞에 둡니다. 공개 GET은 화이트리스트(게시판·랭킹·최신 리뷰·시니어 요청 목록/상세·AI 모델 목록·헬스 체크)뿐이고 나머지는 인증이 필요합니다.
- **메서드 보안**: 관리자 컨트롤러에 `@PreAuthorize("hasRole('ADMIN')")`를 추가로 적용합니다.
- **소유권 검사**: 채팅 이력은 방 참여자만, 시니어 지원자 목록은 요청 작성자만, 리뷰 결과는 요청자·담당 시니어·관리자만 조회할 수 있습니다.
- **WebSocket(STOMP)**: CONNECT에서 JWT 검증, SUBSCRIBE에서 채팅방 참여자/본인 채널/역할 채널 검사, SEND는 정해진 경로만 허용하며 발신자는 인증 정보에서 정합니다.
- **비밀번호**: BCrypt 해시. 변경 시 현재 비밀번호 확인이 필요합니다. 이메일 발송 수단이 없어 자가 재설정은 제공하지 않습니다(관리자 문의).

## 2. 결제·크레딧 무결성
- 결제 검증은 서버가 PortOne API로 재조회합니다(캐시하지 않음). 결제 ID는 DB 유니크로 1회만 사용 가능합니다.
- 금액은 클라이언트 값이 아니라 서버 가격표/허용 금액과 비교하고, 결제 소유자(결제 시 심은 사용자 식별값)가 요청자와 일치해야 합니다.
- 크레딧 증감·시니어 매칭/정산은 행 잠금으로 직렬화하며, 정산은 상태(대기 → 매칭 → 완료)를 검사해 한 번만 처리됩니다.
- 구독 해지 환급은 실제 결제 금액 기준이며 `REFUND` 유형으로 기록해 매출 집계에서 분리합니다.
- 이 서비스의 PortOne 결제는 **테스트(가상) 결제**입니다.

## 3. 입력·출력 보호
- **에러 응답**: 내부 예외 메시지·SQL 원인을 노출하지 않고 일반 문구만 반환합니다. 상세는 서버 로그에만 남깁니다.
- **업로드**: jpg·png·webp·gif만 허용, 5MB 제한, 파일 서명(매직 바이트) 검사, 서버가 파일명 생성.
- **외부 API 키**: 쿼리스트링이 아닌 헤더로 전달합니다(예: Gemini `x-goog-api-key`). 로그에 키·토큰 일부도 남기지 않습니다.
- **소셜 액세스 토큰**: 서비스에서 쓸 곳이 없어 저장하지 않으며, OAuth 권한 범위도 최소(`read:user`, `user:email`)로 둡니다.
- **프로필 이미지 URL**: 자체 업로드 경로·Supabase 공개 경로·DiceBear만 허용합니다.

## 4. 운영 보안
- **비밀값 관리**: `.env`는 로컬 개발용이며 Git에 올리지 않습니다. 필요한 키 이름은 `backend/.env.example`에 값 없이 정리되어 있습니다. 운영에서는 호스팅의 환경변수/시크릿 기능으로 주입하고 Docker 이미지에는 `.env`를 넣지 않습니다.
- **로그 마스킹**: `MaskingUtil`과 `LogMaskingConverter`로 이메일·연락처·로그인 ID를 마스킹합니다.
- **Rate Limiting**: IP별 토큰 버킷(일반 API 초당 약 50회 충전·최대 100, 로그인·회원가입은 분당 10회). 오래 쓰지 않은 버킷은 정리합니다. 클라이언트 IP는 조작할 수 있는 `X-Forwarded-For`의 맨 앞 값이 아니라, 프록시가 덧붙인 오른쪽 항목을 `app.security.trusted-proxy-hops`(운영 `TRUSTED_PROXY_HOPS`, 기본 2)만큼 세어 사용합니다(`ClientIpResolver`). 비회원 AI 리뷰 횟수 제한도 같은 IP 값을 씁니다. 호스팅 프록시 구성이 바뀌면 이 값을 다시 확인해야 합니다.
- **CORS**: `CORS_ALLOWED_ORIGIN`에 지정한 출처만 허용합니다.
- **스토리지**: 서버만 `service_role` 키로 업로드합니다. 클라이언트에는 스토리지 쓰기 권한이 없습니다.

## 5. 아직 하지 않은 것 (정직한 한계)
- mTLS, Zero Trust, Trivy 등 컨테이너 취약점 점검, SCA 자동화 파이프라인은 구성하지 않았습니다.
- 운영 비밀값(JWT 키, DB 비밀번호, 소셜/AI 키)의 정기 교체 절차는 아직 없습니다.
- 비밀번호 정책(길이·복잡도)은 공백 금지 수준입니다.
