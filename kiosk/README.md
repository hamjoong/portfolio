# 키오스크 시스템 Kiosk System

---

## 1. 프로젝트 소개
사용자 친화적인 인터페이스로 복잡한 주문 및 결제 과정을 간소화하는 효율적인 키오스크 솔루션입니다

---

## 2. 프로젝트 개요
- **제작 배경**: 식당이나 카페 등 매장에서의 주문 대기 시간을 줄이고 효율적인 주문 처리를 위해 기획되었습니다
- **기획 의도**: 프론트엔드 UI/UX 구현 능력 강화 및 클라이언트 사이드 데이터 관리 로직을 익히기 위해 설계되었습니다
- **프로젝트 목표**: 서버·DB 없이도 주문부터 결제 영수증까지 이어지는 프론트엔드 지향적 프로토타입 구현

---

## 3. 주요 기능
- **메뉴 선택**: 인기메뉴, 커피, 음료, 디저트 카테고리별 메뉴 선택 (커피는 아이스/핫 전환)
- **옵션 선택**: 매장/포장, HOT/ICE 등 필수 옵션 검증
- **장바구니 관리**: 주문 메뉴 추가, 삭제, 수량 변경(메뉴당 최대 99개) 및 실시간 합계 계산
- **포인트/결제 흐름 (시뮬레이션)**: 휴대폰 번호 11자리 입력 검증과 키패드, 카드 결제 화면 흐름을 구현했습니다. 보유 포인트는 임의 값이며 서버에 저장·차감되지 않습니다
- **주문 내역 처리**: 결제 후 대기번호 생성(브라우저 `localStorage`) 및 영수증 출력

---

## 4. 기술 스택
- **Frontend**: Pug (HTML), SCSS (CSS), JavaScript (ES6+), jQuery
- **Server**: Node.js, Express (정적 파일 서빙 및 Pug 렌더링만 담당)
- **Data Format**: JSON (`build/nodejs/kioskmenu.json`, 인트로 이미지 목록)

---

## 5. 기술 선택 이유
- **Pug & SCSS**: 컴포넌트 단위로 구조를 나누어 복잡한 키오스크 UI의 가독성과 유지보수 효율을 높이기 위해 선택했습니다
- **정적 JSON 메뉴 데이터**: 메뉴 정보를 JSON 파일로 두고 AJAX로 읽어 오므로 서버·DB 의존 없이 화면이 바로 렌더링됩니다

---

## 6. 시스템 아키텍처
```text
[ Client ]  Pug(HTML) / SCSS(CSS) / JavaScript + jQuery
    |-- AJAX: /nodejs/kioskmenu.json, intro2.json
    |-- localStorage: 대기번호
         |
[ Server ]  Express: build/ 정적 서빙 + GET / (kiosk.pug 렌더링)
```

---

## 8. 트러블 슈팅

### 8-1. 안내 모달이 다른 화면에서 보이지 않는 문제
- **문제**: 옵션을 선택하지 않고 "다음"을 누르거나 번호 자릿수가 틀려도 아무 반응이 없다가 메인 화면으로 돌아오면 모달이 떠 있었습니다
- **원인**: 모달(`model_box`)이 메인 화면(`main_box`) 안에 있어서 메인이 숨겨진 다른 화면에서는 모달도 함께 숨겨졌습니다
- **해결**: 모달을 `main_box` 밖 최상위로 옮기고 화면 중앙에 고정(`position: fixed`)했습니다

### 8-2. 옵션 화면에서 뒤로 가도 장바구니에 담기는 문제
- **문제**: 메뉴를 눌러 옵션 화면으로 이동한 뒤 뒤로가기만 해도 상품이 장바구니에 담겼습니다
- **원인**: 메뉴 클릭 한 번에 "장바구니 추가"와 "옵션 화면 이동"이 동시에 실행되었습니다
- **해결**: 메뉴를 누르면 선택한 메뉴만 기억해 두고 필수 옵션 검증을 통과한 뒤 "다음"을 눌렀을 때만 담도록 바꿨습니다 뒤로가기는 기억해 둔 메뉴를 버립니다

### 8-3. 장바구니 수량 조절·삭제가 동작하지 않던 문제
- **문제**: 장바구니에서 `+`/`-` 수량 조절이 안 되는 경우가 있었고 `-`로 항목을 지우는 삭제도 안 되었습니다 담은 메뉴를 한 번에 비우는 휴지통 버튼은 눌러도 목록이 그대로 남아 삭제가 아예 동작하지 않았습니다
- **원인**:
  - 수량 조절·`-` 삭제: 장바구니 항목은 메뉴를 담을 때 `innerHTML +=`로 동적 생성됩니다 이때 컨테이너 전체가 다시 만들어지므로 버튼에 직접 걸어 둔 클릭 이벤트가 사라지거나 새 버튼에는 걸리지 않았습니다.
  - 휴지통 삭제: 삭제 핸들러가 메뉴별 반복문 안에서 메뉴 하나씩 등록되는 구조였고 메뉴 JSON을 불러온 뒤에야 등록되었습니다 전체 삭제라는 역할에 비해 구조가 복잡해 한 번에 비워지지 않았던 것으로 보입니다.
- **해결**:
  - 수량 조절·`-` 삭제: `$(document).on('click', 선택자, …)` 이벤트 위임으로 바꿨습니다 수량이 0이 되면 장바구니·결제 요약·영수증의 해당 항목(`.{메뉴명}_box`)을 함께 제거합니다.
  - 휴지통 삭제: 반복문 밖에서 한 번만 등록하고 모든 메뉴의 수량을 0으로 되돌린 뒤 장바구니·결제 요약·영수증 화면을 한꺼번에 비우도록 했습니다.

### 8-4. 장바구니 합계 금액이 정확하지 않던 문제
- **문제**: 메뉴를 담고 빼는 과정에서 장바구니 합계가 실제 주문과 맞지 않는 경우가 있었습니다
- **원인**: 초기 구현은 메뉴를 담을 때마다 가격을 `price_arr` 배열에 쌓고 그 배열을 더해 합계를 냈습니다 메뉴를 뺄 때는 배열에서 `pop()`으로 마지막 항목을 빼서 빼려는 메뉴와 다른 메뉴의 가격이 빠지거나 합계 계산이 누적되었습니다 수량이 아니라 담은 횟수를 기준으로 하다 보니 수량 조절 결과와도 어긋났습니다
- **해결**: 배열로 이력을 관리하지 않고 합계를 "모든 메뉴의 `가격 × 수량`"으로 그때그때 다시 계산하도록 바꿨습니다 담기·`+`·`-`·삭제 어느 경로로 수량이 바뀌어도 같은 함수(`updateTotalSum`)로 장바구니·결제 요약·영수증 합계가 함께 갱신됩니다

### 8-5. 클릭 핸들러 중복 등록
- **문제**: 장바구니 비우기·영수증 닫기 버튼의 클릭 핸들러가 메뉴 수(21개)만큼 중복 등록되어 한 번 클릭에 21번 실행되었습니다
- **원인**: 메뉴별 반복문 안에서 공통 버튼의 핸들러까지 함께 등록했습니다
- **해결**: 반복문 밖에서 한 번만 등록하고 모든 메뉴를 초기화하도록 정리했습니다

---

## 9. 실행 및 테스트 방법
- **요구사항**: Node.js v14+ 이상
- **설치 및 실행**:
  ```bash
  npm install
  npm start        # = node kioskNode.js
  ```
  브라우저에서 `http://localhost:3030` 접속
- **테스트**: 자동화 테스트 없이 브라우저에서 UI 흐름을 직접 확인합니다.
