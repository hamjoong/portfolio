# 변경 통제 규정 (Change Control)

이 문서는 모든 작업 변경 요청 및 하네스 규칙 변경에 대한 승인과 통제 절차를 정의합니다.

---

## 1. 변경 요청 평가 4단계

1. **영향도 분석**: 변경으로 인해 영향을 받는 모듈 / 인터페이스 / 사이드 이펙트 사전 파악.
2. **사전 보고**: 수정 대상 파일 목록 및 변경 이유를 사용자에게 브리핑.
3. **사용자 승인 (Level 3 필수)**: 외부 환경 변경 / Git 푸시 / 의존성 추가 등은 반드시 사용자의 명시적 승인 후 실행.
4. **결과 검증**: 변경 후 빌드 / 린트 / 테스트 파이프라인을 통과했는지 확인.

---

## 2. 하네스 시스템 변경 통제

* `.Agent/` 내부의 헌법 / 정책 / 역할 정의를 수정하는 것은 **Level 3 작업**에 해당합니다.
* 사용자가 하네스 수정을 요청하거나 개선안이 승인된 경우에만 `.Agent/`를 수정하며 / 변경 내용은 반드시 `.Agent/changes/harness-change-log.md`에 기록합니다.
