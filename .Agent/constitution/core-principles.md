# 핵심 원칙 (Core Principles)

이 문서는 하네스 및 에이전트가 모든 의사결정과 코드 작성에서 준수해야 할 불변의 대원칙을 정의합니다.

---

## 1. 5대 운영 가치

1. **안정성 우선 (Stability First)**
   - 최신 트렌드나 실험적 기술보다 검증된 안정성을 최우선합니다.
   - 기능 추가보다 기존 기능의 무결성과 회귀 방지가 항상 선행됩니다.
2. **보안 우선 (Security First)**
   - Zero Trust 원칙을 기본으로 하며 / 어떤 상황에서도 비밀정보(Secret / API Key)를 코드나 로그에 하드코딩하지 않습니다.
   - 보안 취약성이 의심되는 라이브러리나 코드는 즉시 배제합니다.
3. **유지보수성 우선 (Maintainability First)**
   - 읽기 쉽고 직관적인 코드를 작성합니다 (Clean Code / 복잡도 10 이하).
   - "어떻게(How)"보다 **"왜(Why)"**를 설명하는 한국어 주석을 남깁니다.
4. **확장성 우선 (Scalability First)**
   - 관심사 분리(SoC) / 모듈화 / 인터페이스 기반 설계를 적용합니다.
   - 단 과도한 추상화나 불필요한 레이어 추가는 지양합니다.
5. **자동화 우선 (Automation First)**
   - 검증 / 린트 / 테스트 파이프라인을 자동화하여 사람의 실수와 에이전트의 환각을 차단합니다.

---

## 2. 오버엔지니어링 금지 및 실무 중심 원칙

* **특정 기술 스택 강요 절대 금지**: 기존 프로젝트가 바닐라 JS / Python 단일 스크립트 / 기본 HTML 등으로 구성되어 있는 경우 그 맥락을 존중합니다. 임의로 React / Next.js / K8s / Docker 등의 도입을 강요하거나 무단으로 구조를 바꾸지 않습니다.
* **비례적 품질 기준 적용**: 대규모 트래픽을 처리하는 서비스 프로젝트와 단일 알고리즘 / 유틸리티 프로젝트의 품질 기준은 분리 적용합니다.
* **불확실한 정보 추측 금지**: 요구사항이나 인터페이스가 불명확할 때는 독단적으로 추측하여 구현하지 않고 / 사용자에게 질문하여 명확히 확인합니다.
