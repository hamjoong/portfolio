# 안전 수칙 (Safety Rules)

이 문서는 하네스 시스템에서 에이전트가 절대로 위반해서는 안 되는 안전 통제선(Safety Guardrails)을 정의합니다.

---

## 1. 절대 금지 사항 (Hard Prohibitions)

1. **GitHub Repository 및 원격 브랜치 삭제 절대 금지**
   - 어떠한 상황에서도 저장소 삭제 명령이나 원격 메인 브랜치 강제 삭제(`git push --delete` / `gh repo delete`)를 자동 실행하지 않습니다.
2. **비밀정보 하드코딩 및 유출 절대 금지**
   - API Key / DB 비밀번호 / JWT 시크릿 / 개인 식별 정보(PII)를 코드 / 문서 / 주석 / 커밋 메시지 / 콘솔 로그에 직접 기록하지 않습니다.
   - 환경 변수는 `.env` 또는 보안 매니저를 활용하며 `.env` 자체는 커밋 대상에서 제외합니다.
3. **독립 프로젝트 간 교차 오염(Cross-Contamination) 금지**
   - 한 번의 작업에서 복수의 프로젝트 파일을 동시에 임의 수정하지 않습니다. 사용자가 "devcodehub 수정해줘"라고 했다면, `shoppingmall`나 `blog3`의 파일은 단 1바이트도 수정되어서는 안 됩니다.
4. **미승인 Level 3 실행 금지**
   - 사용자 허락 없이 `git commit` / `git push` / 패키지 설치(`npm i` / `pip install`) / DB 마이그레이션을 임의로 백그라운드에서 진행하지 않습니다.

---

## 2. 안전 롤백 및 복구 보장

* 파일 수정 전 또는 중요 작업 수행 전 / 변경 전 상태로 안전하게 롤백할 수 있는 준비를 갖춥니다.
* 에이전트의 작업 중 빌드 오류 / 테스트 실패가 발생하면 실패 상태로 방치하지 않고 즉시 원인을 분석하여 사용자에게 보고합니다.
