# 권한 계층 및 우선순위 (Authority and Priority)

하네스는 모든 작업 행위를 4단계 레벨로 엄격히 통제합니다.
에이전트는 상위 레벨의 승인 없이 작업을 격상하여 수행할 수 없습니다.

---

## 1. 4단계 권한 계층 정의

### Level 0 — Read (단순 조회)
* **정의**: 시스템과 프로젝트 상태의 단순 읽기 작업.
* **허용 범위**: 파일 읽기 / 디렉터리 목록 조회 / 설정 파일 조회.
* **통제 기준**: 시스템 변경이 0바이트여야 하며 / 자율 실행 허용.

### Level 1 — Analyze (심층 분석)
* **정의**: 무변경 원칙 하에 소스 / 구조 / 의존성 / 테스트 / 문서 / Git 상태를 분석.
* **허용 범위**:
  - 소스 코드 흐름 분석 / 아키텍처 다이어그램 도출
  - 정적 분석 도구(Dry-run) 실행
  - Git 상태 조회: `git status` / `git diff` / `git log` / `git branch` (조회 전용)
* **통제 기준**: 소스 코드나 워크스페이스에 일체의 쓰기/변형이 발생하지 않는 분석 전용 단계 자율 실행 허용.

### Level 2 — Project Modification (명시적 프로젝트 변경)
* **정의**: 사용자가 명시적으로 지시한 특정 대상 프로젝트의 파일 추가 / 수정 / 삭제
* **허용 범위**: 오직 지정된 프로젝트 내부 파일로 한정됨
* **통제 기준**:
  - 타 프로젝트 또는 워크스페이스 루트의 파일 수정 절대 금지
  - 사용자의 명시적 프롬프트 지시 범위 내에서만 실행

### Level 3 — Controlled Operations (통제된 시스템/환경 변경)
* **정의**: 시스템 / 환경 / 저장소 상태를 영구적으로 변경하거나 외부와 통신하는 모든 파괴적 중요 작업.
* **통제 대상 목록**:
  - **Git 쓰기 및 조작**: `git add` / `git commit` / `git push` / `git pull` / `git merge` / `git rebase` / `git reset` / `git clean`
  - **GitHub 작업**: Issue 생성 / 수정 / PR 생성 / 수정 / Merge (※ **GitHub repository 삭제는 절대 자동 실행 금지**)
  - **패키지 설치 및 의존성 변경**: `npm install` / `pip install` / `apt install` / `pom.xml`/`package.json` 의존성 추가
  - **인프라 및 런타임 제어**: `docker compose up/down` / DB migration / `.env` 파일 변경 / CI/CD 설정 변경
  - **하네스 자체 변경**: `.Agent/` 하위 정책 / 규칙 / 스크립트 수정
* **통제 기준**: **반드시 사전에 사용자에게 변경 계획과 영향도를 설명하고 용자의 명시적 승인(Confirmation)을 획득한 후 실행**.
