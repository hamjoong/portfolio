# Antigravity Agent 총괄 헌장

이 문서는 `portfolio` 단일 워크스페이스를 통제하는 **단일 하네스(Single Harness)의 최상위 오케스트레이터 및 실행 진입점**입니다.
Antigravity CLI 환경에서 Gemini AI 에이전트는 사용자의 모든 요청을 처리하기 전 본 헌장과 하네스 규칙을 최우선으로 준수해야 합니다.

---

## 1. 하네스 엔지니어링 4대 기본 철학

1. **단일 워크스페이스 & 프로젝트 경계 격리 (Single Workspace & Project Isolation)**
   - `portfolio` 폴더는 단 하나의 워크스페이스이며 / 오직 `.Agent/`만이 이를 통제하는 유일한 하네스입니다.
   - 워크스페이스 내 모든 하위 프로젝트(`devcodehub` / `shoppingmall` / `blog3` 등)는 상호 독립적인 단위입니다.
   - 프로젝트별 개별 하네스를 임의 생성하지 않으며 / 작업 대상이 아닌 타 프로젝트의 파일에 일체 접근/변경하지 않습니다.

2. **작업 권한 계층화 (Tiered Permission Model: Level 0 ~ Level 3)**
   - **Level 0 (Read)**: 파일 단순 조회 (무변경 보장)
   - **Level 1 (Analyze)**: 소스 / 의존성 / 빌드 / Git 상태 무변경 심층 분석
   - **Level 2 (Project Modification)**: 사용자가 명시적으로 지시한 프로젝트 단일 변경
   - **Level 3 (Controlled Operations)**: Git 쓰기/원격 / 패키지 설치 / 인프라 / DB 변경 / 하네스 변경 -> **사전 승인 필수**

3. **10대 시니어 전문가 동적 오케스트레이션 & 프로젝트별 맞춤 적용**
   - [GEMINI.md](file:///mnt/d/Program%20Files/Developer/portfolioproject/portfolio/GEMINI.md)에 정의된 10대 직무(Frontend / Backend / DBA / Security / QA / Infra / 등)를 상황에 맞게 선별 호출합니다.
   - **기술 강요 금지 및 오버엔지니어링 절대 방지**: 경량 스크립트 / 알고리즘 프로젝트에 무리하게 엔터프라이즈 프레임워크나 복잡한 인프라를 강요하지 않고 / 각 프로젝트의 실제 체급과 용도에 맞춰 비례 적용합니다.

4. **하네스 자기 진화 메커니즘 (Continuous Harness Evolution)**
   - 에이전트 실패 / 버그 / 사용자 이슈 제기 시 원인을 분석 기록(`incidents/`)하고 / 개선안(`improvements/`)을 작성하여 사용자 승인 후 하네스 규칙(`changes/`)에 반영합니다.

## 2. 작업 수신 시 표준 실행 라이프사이클

모든 사용자 프롬프트 수신 시 에이전트는 다음 단계를 순차적으로 밟습니다:

```
[사용자 요청 수신]
       ↓
[1단계: 작업 대상 및 레벨 판정]
   - 대상 프로젝트 식별
   - 작업 레벨 판정 (Level 0, 1, 2, 3)
   - Level 3 작업 포함 여부 확인 (포함 시 사용자 승인 필요)
       ↓
[2단계: 대상 프로젝트 프로파일링 & 역할 배정]
   - 프로젝트 체급 분석 (Tier 1: 스크립트, Tier 2: 클라이언트, Tier 3: 풀스택/서비스)
   - 10대 전문가 중 필요한 페르소나 최소 선별 (단일 또는 협업)
       ↓
[3단계: 작업 실행 (Level 2 범위 내)]
   - Why 중심의 한국어 주석 작성 원칙 준수
   - Clean Code / SOLID / 복잡도 10 이하 / 깊이 3 이하 준수
   - 작업 대상 외 다른 프로젝트 파일 수정 엄격 차단
       ↓
[4단계: 품질 검증 파이프라인]
   - 정적 분석 / 린트 / 테스트 검증
   - 미작업 프로젝트의 Diff가 발생하지 않았는지 무결성 체크
       ↓
[5단계: 최종 보고]
   - 정확하고 쉬운 한국어로 명확하게 결과 요약
```

## 3. 하네스 참조 디렉터리 맵

| 디렉터리 | 주요 내용 및 규정 |
| :--- | :--- |
| **`constitution/`** | [최고 헌법] 핵심 원칙 / 안전 수칙 / 권한 등급 / 프로젝트 경계 수칙 |
| **`roles/`** | [10대 전문가] 직무별 R&R / 오케스트레이션 엔진 / 프로젝트 맞춤형 선별 기준 |
| **`policies/`** | [운영 정책] 파일 변경 / 격리 / Git / GitHub 통제 / 주석(Why) / 문서화 표준 |
| **`workflows/`** | [워크플로우] 작업 흐름 / 분석 절차 / 다중 에이전트 협업 / 하네스 개선 절차 |
| **`documentation/`** | [문서 가이드] README 템플릿 / 주석 가이드 / 마크다운 표준 / GEMINI 10대 문서 양식 |
| **`quality/`** | [품질 기준] 12단계 검증 파이프라인 / 코딩 표준 / 기술 부채 관리 |
| **`knowledge/`** | [지식 베이스] 프로젝트 레지스트리 / 환경 명세(WSL2/Ubuntu) / 용어집 |
| **`incidents/` & `improvements/`** | [자가 개선] 이슈 / 장애 트래킹 및 하네스 규칙 개선 승인 이력 |
| **`scripts/`** | [자동화 검증] 워크스페이스 무결성 / 단일 프로젝트 검증 셸 스크립트 |
