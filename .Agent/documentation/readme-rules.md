# README 작성 표준 규칙 (README Rules)

이 문서는 사용자의 지시로 개별 프로젝트의 `README.md`를 작성하거나 업데이트할 때 준수해야 할 원칙과 필수 항목을 정의합니다.

---

## 1. 사전 분석 및 특성 반영 원칙

* `README.md`를 작성하기 전 / 반드시 대상 프로젝트를 **Level 1 (Analyze)** 단계로 분석합니다.
* 프로젝트의 실제 기술 스택(바닐라 JS / React / Node.js 등) / 프로젝트 목적(단순 유틸 / 프론트엔드 앱 / 풀스택 서비스)에 맞춰 유연하고 진실되게 기술합니다. (허위 스택이나 과장된 엔터프라이즈 구조 기재 금지)

---

## 2. 필수 포함 섹션 템플릿

개별 프로젝트의 `README.md`는 최소한 다음의 항목을 포함하여 완성도 있게 구성해야 합니다:

```markdown
# [프로젝트명]

---

## 1. 프로젝트 소개
- 타겟 사용자 및 서비스의 핵심 가치 한 줄 요약

---

## 2. 프로젝트 개요
- 제작 배경
- 기획 의도
- 프로젝트 목표 중심

---

## 3. 주요 기능
- 핵심 기능을 사용자 관점 목록 및 설명
- 주요 화면 또는 기능 동작 흐름

---

## 4. 기술 스택 및 선택 이유
- 사용 기술 (언어, 프레임워크, 라이브러리, DB 등)
- 해당 기술을 선택한 현실적이고 실무적인 이유

---

## 5. 시스템 아키텍처 및 프로젝트 구조
- 계층 구조 및 모듈 간 관계 (서버 / DB / 외부 API / 등의 관계를 다이어그램으로 표현)
- 디렉터리 구조 트리 (디렉터리 다이어그램으로 표현)

---

## 6. 트러블슈팅 및 성능 최적화
- 개발 중 직면했던 문제 와 원인 구체적인 해결 과정 결과 (Why/How)
- 성능 개선 포인트 (렌더링 최적화 / 쿼리 튜닝 / 번들 크기 절감 등 / 개선 전/후 수치와 측정 방법)

---

## 7. 실행 및 테스트 방법
- 로컬 환경 요구사항 (Node 버전, 브라우저 등)
- 설치 및 실행 명령어 (`npm install` / `npm start` / 등)
- 테스트 실행 방법

---
