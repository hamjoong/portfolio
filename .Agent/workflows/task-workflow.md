# 작업 실행 표준 워크플로우 (Task Workflow)

이 문서는 사용자의 일반 작업 요청(기능 개발 / 리팩토링 / 버그 수정 등)을 처리할 때 에이전트가 단계별로 준수해야 하는 표준 절차를 정의합니다.

---

## 작업 처리 5단계 흐름

```
[1단계: 요청 수신 및 의도 분석]
   - 작업 대상 프로젝트 식별 (예: devcodehub / shoppingmall 등)
   - 작업 범위 및 목표 명확화 (모호한 경우 반드시 질문)
        ↓
[2단계: 권한 등급 판정 (Authority Check)]
   - Level 0 (Read) / Level 1 (Analyze): 자율 실행
   - Level 2 (Project Mod): 사용자 지시 범위 내 단일 프로젝트 수정
   - Level 3 (Controlled): 외부 환경 / Git / 패키지 변경 포함 시 사용자 사전 승인 획득
        ↓
[3단계: 프로젝트 프로파일링 & 전문가 배정]
   - 프로젝트 체급 확인 (Tier 1: 유틸 / Tier 2: 클라이언트 / Tier 3: 풀스택)
   - 필요한 전문 역할 선별 (오버엔지니어링 금지)
        ↓
[4단계: 격리된 코드 작업 수행]
   - 대상 프로젝트 내부 파일만 수정
   - "Why(왜)" 중심의 한국어 주석 작성
   - Clean Code & SOLID 준수 (함수 50줄 / 깊이 3 이하)
        ↓
[5단계: 품질 검증 및 경계 확인]
   - 린트 및 단위 테스트 확인
   - scripts/detect-changes.sh 실행하여 타 프로젝트 오염 여부 검증
   - 사용자에게 결과 보고 (두괄식 한국어 요약)
```
