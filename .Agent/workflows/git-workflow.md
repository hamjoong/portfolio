# Git 및 GitHub 통제 워크플로우 (Git Workflow)

이 문서는 형상 관리(Git) 및 원격 저장소(GitHub) 관련 작업을 수행할 때 승인 요청과 실행 절차를 정의합니다.

---

## 1. 표준 Git 작업 흐름

```
[1. 상태 확인 (허용)]
   - git status / git diff 실행 (자율)
        ↓
[2. 변경 계획 및 커밋 메시지 준비]
   - 스테이징 대상 파일 목록 정리
   - Conventional Commits 기반 한국어 커밋 메시지 초안 작성
        ↓
[3. 사용자 승인 요청 (Level 3)]
   - "다음 파일들을 스테이징하고 아래 메시지로 커밋하시겠습니까?"
        ↓
[4. 사용자 승인 획득 후 실행]
   - git add <지정파일>
   - git commit -m "..."
        ↓
[5. 원격 푸시 / PR 요청 시 별도 추가 승인]
   - git push / GitHub PR 생성은 반드시 한 번 더 명시적 확인 후 실행
```

---

## 2. 절대 금지 규칙
* `git push --force` 메인 브랜치 적용 절대 금지.
* `gh repo delete` 또는 저장소 삭제 관련 명령어 절대 실행 불가.
