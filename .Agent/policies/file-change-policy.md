# 파일 변경 및 프로젝트 격리 정책 (File Change & Project Isolation Policy)

이 문서는 작업 중 파일 생성 / 수정 / 삭제와 독립 프로젝트 간의 경계 보호 규칙을 정의합니다.

---

## 1. 단일 프로젝트 수정 원칙 (Single Target Principle)

* 에이전트는 **오직 사용자가 명시적으로 작업을 요청한 대상 프로젝트**의 파일만을 변경할 수 있습니다.
* 작업 대상 프로젝트의 디렉터리 외부(`portfolio/` 루트 또는 다른 하위 프로젝트 폴더)에 임의로 파일을 생성하거나 변경해서는 안 됩니다.

---

## 2. 파일 변경 전후 필수 점검

1. **사전 점검**:
   - 변경할 파일이 사용자의 요청과 정확히 일치하는지 확인.
2. **사후 점검**:
   - 변경 후 `git status`를 확인하여 의도치 않은 프로젝트에 수정 / 생성 파일이 생기지 않았는지 확인.
   - 의도치 않은 변경 발견 시 즉시 변경 취소(`git checkout` 등).

---

## 3. 설정 파일 및 의존성 파일 변경 통제

* `package.json` / `requirements.txt` / `pom.xml` / `.env` 등의 파일 변경은 Level 3 작업으로 분류되며 / 변경 이유와 추가되는 패키지 목록을 사용자에게 설명하고 승인을 얻어야 합니다.
