# 파일 변경 및 프로젝트 격리 정책 (File Change & Project Isolation Policy)

이 문서는 작업 중 파일 생성 / 수정 / 삭제와 독립 프로젝트 간의 경계 보호 규칙을 정의합니다.

---

## 1. 단일 프로젝트 수정 원칙 (Single Target Principle)

* 에이전트는 **오직 사용자가 명시적으로 작업을 요청한 대상 프로젝트**의 파일만을 변경할 수 있습니다.
* 작업 대상 프로젝트의 디렉터리 외부(`portfolio/` 루트 또는 다른 하위 프로젝트 폴더)에 임의로 파일을 생성하거나 변경해서는 안 됩니다. (루트의 하네스 자체 개선 작업 제외)
* 다른 프로젝트를 조사하거나 분석하기 위해 파일을 읽는 행위(Level 0/1)는 자유롭게 허용됩니다.

---

## 2. 파일 변경 전후 필수 점검

1. **사전 점검**:
   - 변경할 파일이 사용자의 요청과 정확히 일치하는지 확인.
2. **사후 점검**:
   - 변경 후 `git status` 또는 `.Agent/scripts/validate-workspace.sh <대상프로젝트>`를 실행하여 의도치 않은 프로젝트에 수정 / 생성 파일이 생기지 않았는지 확인.
   - 의도치 않은 변경 발견 시 무단으로 롤백하지 않고, **변경의 출처와 소유자(사용자가 작업 중이던 파일인지 여부)를 먼저 확인한 후** 사용자 승인 하에 처리.

---

## 3. 설정 파일 및 의존성 파일 변경 기준

1. **프로젝트 내부 설정/의존성 변경 (Level 2/3 경계)**:
   - 사용자가 명시적으로 지시한 특정 기능 구현을 위해 프로젝트 내부의 `package.json`, `pom.xml`, `requirements.txt`에 라이브러리를 추가하거나 수정하는 것은 사전에 필요성을 명시하고 진행합니다.
   - 새로운 글로벌 패키지 설치(`npm install -g`, `apt install`)나 파괴적인 메이저 버전 변경은 **Level 3 작업**으로 분류되어 사용자 사전 승인이 필수입니다.
2. **보안 민감 설정 (.env)**:
   - `.env` 파일은 절대 Git 추적 대상에 포함시키지 않으며, 반드시 `.gitignore`에 등록 관리합니다.
