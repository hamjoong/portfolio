# Git 및 GitHub 운영 정책 (Git & GitHub Policy)

이 문서는 Git 명령어 실행 및 GitHub 상호작용 시의 통제 권한과 행동 규칙을 정의합니다.

---

## 1. 명령어별 권한 매트릭스

| 명령어 / 액션 | 승인 필요 여부 | 세부 제약 사항 |
| :--- | :--- | :--- |
| `git status` | **허용 (자율 실행)** | 무변경 상태 점검용 |
| `git diff` | **허용 (자율 실행)** | 변경 내용 확인용 |
| `git log` | **허용 (자율 실행)** | 히스토리 파악용 |
| `git branch` (조회) | **허용 (자율 실행)** | 현재 브랜치 확인용 |
| `git add` | **승인 필요** | 스테이징 대상 파일 명시 필요 |
| `git commit` | **승인 필요** | 커밋 메시지 사전 보고 및 승인 |
| `git push` | **승인 필요** | 원격 저장소 대상 브랜치 확인 |
| `git pull` | **승인 필요** | 컨플릭트 가능성 사전 고지 |
| `git merge` / `git rebase` | **승인 필요** | 병합 전략 및 대상 확인 |
| `git reset` / `git clean` | **승인 필요** | 데이터 유실 위험 안내 |
| **GitHub Issue 생성/수정** | **승인 필요** | 본문 및 라벨 사전 확인 |
| **GitHub PR 생성/수정/Merge** | **승인 필요** | PR 요약 및 베이스 브랜치 확인 |
| **GitHub Repository 삭제** | **절대 자동 실행 금지** | 에이전트 실행 불가 (Blacklist) |

---

## 2. 커밋 메시지 표준 규칙

* 커밋 메시지는 **프로젝트 내용에 맞는 적절한 한국어 설명**으로 작성합니다.
* 형식은 Conventional Commits 표준 구조를 준수합니다:

  ```text
  <타입>(<프로젝트명>): <한국어 요약>

  - 상세 작업 내용 1 (Why 중심)
  - 상세 작업 내용 2
  ```
  - 예시: `feat(kiosk): 결제 실패 시 자동 재시도 및 친절한 안내 팝업 추가`
