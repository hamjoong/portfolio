# [가이드] 범용 제품 요구사항 정의서 (Universal PRD Guide)

---

## 1. 개요 및 목적
본 문서는 웹, 모바일, 백엔드, AI/ML, 인프라 등 **모든 소프트웨어 프로젝트에 범용적으로 적용할 수 있는 표준 제품 요구사항 정의서(PRD) 작성 가이드이자 실행 템플릿**입니다.

OpenAI 하네스 엔지니어링의 기본 원칙에 따라, AI 에이전트는 기획 단계에서 사용자의 요구를 자의적으로 해석하지 않고 측정 가능한 정량적 사양으로 구조화해야 합니다. 본 문서는 전체 개발 라이프사이클의 기준점이 되는 **단일 진실 공급원(Single Source of Truth, SSOT)** 역할을 합니다.

---

## 2. 에이전트 작성 원칙 (Core Rules)
1. **정량적 목표 필수 (Quantifiable Targets)**: "빠른 처리 속도", "높은 사용성"과 같은 주관적 서술을 금지한다. 반드시 지연시간(Latency), 동시 접속자 수, 가용성, 에러율 등 구체적인 수치(SLO)를 기재한다.
2. **범위의 명확한 경계선 설정 (Scope Boundary)**: MVP에 포함할 핵심 기능(In-Scope)과 이번 주기에서 개발하지 않을 기능(Out-of-Scope)을 명확히 분리하여 작업 범위가 무분별하게 팽창(Scope Creep)하는 것을 차단한다.
3. **[Gate 1] 승인 선행 (No Code before Approval)**: PRD 작성이 완료되고 담당 엔지니어(사람)의 명시적 승인을 받기 전까지는 하위 기술 설계(TRD)나 실제 코드 구현을 절대 시작하지 않는다.

# [템플릿] 프로젝트 PRD 실행 양식 (Universal PRD Template)
*신규 프로젝트 기획 시 아래 템플릿을 복사하여 메타데이터와 세부 항목을 구체화합니다.*

```markdown
---
project_name: "{{프로젝트명}}"
version: "1.0.0"
author_squad: "Strategy Squad"
status: "DRAFT | IN_REVIEW | APPROVED"  # APPROVED 완료 시 Gate 1 통과
approved_by: "null | {{승인자 성명/직책}}"
created_at: "{{YYYY-MM-DD}}"
updated_at: "{{YYYY-MM-DD}}"
---

# 1. 제품 개요 및 핵심 가치 (Product Overview)
- **한 줄 요약**: {{이 제품이 무엇이며 누구를 위한 것인지 한 문장으로 정의}}
- **비즈니스 목적**: {{제품 출시로 얻고자 하는 궁극적인 비즈니스 가치}}

# 2. 문제 정의 및 대상 사용자 (Problem & Personas)
- **해결하고자 하는 문제**:
  1. {{문제 1}}: {{현재 사용자가 겪고 있는 명확한 비효율 또는 불편}}
  2. {{문제 2}}: {{기존 솔루션의 한계점 또는 시장의 공백}}
- **대상 사용자 (Personas)**:
  - **주요 사용자 (Primary Persona)**: {{서비스의 핵심 기능을 매일 사용하는 핵심 타겟}}
  - **보조 사용자 (Secondary Persona)**: {{관리자, 운영자, 내부 모니터링 담당자 등}}

# 3. 프로젝트 범위 (Scope Management)
- **핵심 개발 범위 (In-Scope - MVP)**:
  - [ ] {{기능 1}}: {{동작 방식 및 세부 사양}}
  - [ ] {{기능 2}}: {{동작 방식 및 세부 사양}}
- **제외 범위 (Out-of-Scope)**:
  - {{차기 버전으로 연기하거나 명시적으로 개발하지 않을 사항}}
- **타협 불가능한 제약 조건 (Non-Negotiables)**:
  - {{법적 규제(개인정보보호법 등), 배포 마감일, 필수 연동 레거시 시스템}}

# 4. 성공 지표 및 목표치 (KPIs & SLO)

| 구분 | 지표명 (Metric) | 목표치 (Target) | 측정 도구 및 방식 |
| :--- | :--- | :--- | :--- |
| **비즈니스** | {{예: 일간 활성 사용자(DAU)}} | {{예: 10,000명}} | {{데이터 분석 대시보드}} |
| **성능 (SLO)** | API 응답 시간 (p95) | 200ms 이하 | APM / 분산 트레이싱 |
| **신뢰성 (SLO)**| 시스템 가용성 (Uptime) | 99.9% 이상 | 헬스체크 모니터링 |
| **품질 (SLO)** | 테스트 커버리지 | 80% 이상 | CI 파이프라인 검증 |

# 5. 핵심 사용자 시나리오 (User Journeys)
- **정상 흐름 시나리오 (Happy Path)**:
  1. 사용자가 {{행동 1}}을 수행한다.
  2. 시스템은 {{처리 1}}을 검증하고 {{결과 1}}을 반환한다.
- **예외 및 실패 시나리오 (Edge & Failure Cases)**:
  1. 외부 시스템 연동 장애 또는 비정상 입력이 발생한다.
  2. 시스템은 {{장애 복구/Fallback 로직}}을 수행하고 사용자에게 안전한 안내를 제공한다.

# 6. [Gate 1] 기획 승인 체크리스트 (Approval Gate)
- [ ] 해결하려는 문제와 목표치가 측정 가능한 수치(SLO)로 정의되었는가?
- [ ] MVP 개발 범위와 제외 범위의 경계가 명확한가?
- [ ] 기술적으로 실현 불가능한 요구사항이 포함되어 있지 않은가?
- [ ] **담당 엔지니어(사람)가 위 내용을 검토하고 승인하였는가?**
```
